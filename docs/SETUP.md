# Setup guide

## Requirements

- Python 3.11 or newer (3.12 tested)
- Windows, macOS or Linux
- Optional: [Ollama](https://ollama.com/download) for local model generation
- Optional: Docker Desktop for the container stack (not verified on the build machine)

## 1. Install

Windows PowerShell, from the project folder:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -e .
```

macOS or Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt -e .
```

## 2. Run the web app

```powershell
.\.venv\Scripts\python.exe -m marketmind
```

Create an account on the sign-in page the first time you open the app. Each account gets its own company knowledge, plans, leads, approvals, feedback, and workflow checkpoints.

Options: `--port 8080`, `--host 0.0.0.0`, `--no-browser`. Sign in before opening API documentation at `/docs` or metrics at `/metrics`.

Passwords must be at least 12 characters. Sessions use an HttpOnly, SameSite cookie that normally ends when the browser closes; the server also expires stored sessions after 30 days. Account and session records are stored in `data/output/accounts.sqlite`; each user's records are in a separate folder below `data/output/users`.

Registration is open and there is no email verification, password reset, or account administration. This prototype is not ready to be exposed directly to the public internet. For a TLS-terminated deployment, set `AUTH_COOKIE_SECURE=true` so browsers only send the login cookie over HTTPS.

## 3. First use

The web app guides the main task in four steps:

1. **Company information**: click *Load sample company* and review the synthetic profile, or enter approved facts about your own company. Click *Save knowledge*.
2. **Campaign setup**: the audience and offer default to the saved profile when available. Change them if needed; the app asks you to confirm when the audience differs from the saved target customer.
3. **Draft review**: click *Create campaign drafts*. The guided workflow creates profile-based template drafts, checks them, and shows the draft content for review. These drafts are not generated by a language model.
4. **Approval**: review the campaign summary, all draft text, and supporting evidence. You can edit one channel, save the change, then review the changed version before approving. Approval records a mock action only; nothing is sent or published.

Search, lead qualification, feedback, and evaluation are available under **More tools**. The experimental plan tool can optionally call Ollama; it reports whether the result was model-generated or whether a template fallback was used. Do not describe a fallback as model output.

The first evidence search downloads the FastEmbed model (internet required once).

## 4. Local model (optional)

```powershell
ollama pull qwen3:4b
.\.venv\Scripts\python.exe scripts\check_ollama.py
```

The status bar in the web app shows whether Ollama is reachable and the configured model is installed. Change the provider, model, or URL with `config/config.json` or the environment variables in `.env.example`. The guided campaign workflow does not require a model. The optional experimental plan action reports model-generation success or a template fallback; standalone channel drafts are template-based.

OpenRouter is supported through `LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY` and `OPENROUTER_MODEL`. Never commit a key.

## 5. Desktop apps (optional)

Install the project first using section 1, then run a desktop app from the project folder in PowerShell:

```powershell
.\.venv\Scripts\python.exe apps\desktop\knowledge_app.py
```

This opens the Company Knowledge window. The desktop tools are separate windows rather than one combined launcher. To open another tool, close the current window and run its script instead:

```powershell
.\.venv\Scripts\python.exe apps\desktop\retrieval_app.py
.\.venv\Scripts\python.exe apps\desktop\content_app.py
.\.venv\Scripts\python.exe apps\desktop\planner_app.py
.\.venv\Scripts\python.exe apps\desktop\feedback_app.py
.\.venv\Scripts\python.exe apps\desktop\leads_app.py
.\.venv\Scripts\python.exe apps\desktop\evaluation_app.py
```

Each app reads and writes the legacy shared files in `data/output`; desktop tools do not use web-app accounts or per-user workspaces. No web server is needed for the desktop tools.

## 6. Test

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src apps tests scripts eval
$env:PYTHONPATH = "src"; .\.venv\Scripts\python.exe scripts\eval_gate.py
.\.venv\Scripts\python.exe scripts\retrieval_eval.py
.\.venv\Scripts\python.exe scripts\report_guardrails.py
```

The evaluation gate exits non-zero when the guardrail evaluation is below `evaluation.minimum_pass_rate` in `config/config.json`. It currently **fails**, because the keyword guardrail catches only 13 of 30 attacks. See [EVALUATION_REPORT.md](EVALUATION_REPORT.md).

## 7. Docker (unverified)

```powershell
docker compose up --build
```

Defines the app on :8000, four FastMCP services, Prometheus on :9090 and Grafana on :3000. Docker Compose has not been verified on this machine. Ollama runs on the host and is reached through `host.docker.internal`.

## Generated files

Everything the apps write goes to `data/output` (git-ignored): account/session database and separate per-user knowledge, retrieval results, FastEmbed cache, plans, drafts, leads, feedback, lessons, approval records and SQLite workflow checkpoints. Deleting the output folder removes accounts and their saved data.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: marketmind` | Install with `-e .` or set `PYTHONPATH=src` |
| Status shows *Local model offline* | Start Ollama |
| Status shows *Model not installed* | `ollama pull qwen3:4b` |
| Plan or drafts return 409 | Save company knowledge first |
| Plan returns 400 | The input guardrail blocked the request text |
| Port already in use | `python -m marketmind --port 8080` |
